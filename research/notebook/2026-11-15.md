## Code
- **Flaky tests fixed at the root.** Two exactness tests failed on ~38% of seeds (worst 2.2× over
  tolerance), and the server hit one. Cause: the review fix made `attend_mixed` always compute in float32,
  while the tests passed float64 inputs and kept float64 tolerances. Now the reference math computes in
  at-least-float32 (`_acc`: bf16 → float32, float64 stays float64). Over 200 seeds the exactness checks sit
  at ~1e-9 of their tolerance, and no check comes within 4× of its tolerance.
- Local test environment matching the server: Python 3.12, torch 2.15.0, transformers 5.23.0 (CPU).
- **Tiny Qwen3-VL** (`cuekeep.testing.tiny_qwen3vl`): random weights, real architecture, tokenizer and image
  processor. Runs the model-facing code end to end on CPU.
- **Gate dump implemented** (`scripts/dump_visual_kv.py`, `configs/dump/gate.yaml`): generate, then one
  teacher-forced pass with a temporary SDPA wrapper capturing queries, visual K/V and the text-key summary.
  - Checked on the tiny model: teacher forcing reproduces greedy decoding 40/40 tokens (float32 and bf16).
  - The capture reconstructs the model's attention output to 6.5e-7 with float32 storage; bf16 storage
    costs 1.7e-3, under G2's 1e-2 capture threshold.
  - The dump → E003 → E001 chain runs on CPU and on MPS (catches device-placement bugs).
- Loaders: ScreenSpot-Pro local release + VLMEvalKit's GUI-click prompt + click scoring under both the
  0–1000 (Qwen3-VL) and pixel conventions. MathVista testmini (real data checked: 1,000 rows).
- Tests: 54 + 3 accelerator tests pass locally (CPU, plus MPS for the accelerator tests).
