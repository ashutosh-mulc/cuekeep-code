## Done
- Code review of the first implementation against `method.md`, then fixes. Each choice and its
  reasoning is in [decisions/0004](../decisions/0004-review-fixes-scoring-memory-fetch.md). In brief:
  - The stand-in math was already right: exact for identical keys, full residency equals full
    attention, the covariance factor is the population covariance.
  - Fixed:
    - cross-head score aggregation (per-head attention shares);
    - an unbounded covariance correction (capped mode; default `cov_rank: 0`);
    - a memory metric that included prefill and weights (visual-KV bytes, decode-phase peak, KV breakdown);
    - a fetch path that was synchronous and could read half-copied slots (pending→committed protocol, region-contiguous pinned host store);
    - loaders that decoded whole datasets (subset first);
    - ambiguous box formats (explicit `bbox_format`);
    - ms/token that included prefill;
    - truncation not being flagged;
    - forced greedy decoding (model-default sampling, per-sample seeds);
    - a misleading E001 synthetic setup;
    - a `SlotPool` same-step eviction bug.

## Observations (E001 phase A smoke; synthetic, not results)
- Run: `runs/E001-pooled-attention-fidelity/*-review-fix-smoke` (1.5 s on CPU).
- Capped vs quadratic correction:
  - At logit std ≈ 11, g=2: mass top-8 recall is 0.811 capped vs 0.547 quadratic, vs 0.758 plain.
  - At g=4 the capped score is below plain (0.663 vs 0.723). So the correction is not a clear win
    yet; it stays off by default.
- Every score variant predicts the oracle benefit of fetching only weakly (Spearman 0.2–0.57), so I
  opened Q10. If this holds on real keys, the fetch-priority rule needs work.
- Aggregation: no difference between raw max and per-head shares on this synthetic data, which has
  no loud heads attending to text. Real dumps decide (Q12).

## Experiment design reworked into staged gates
- The first plan went straight to full-size runs. It is now staged
  ([experiment_design.md](../experiment_design.md), [decisions/0005](../decisions/0005-staged-gates.md)):
  eight gates, G0–G7, on fixed dev-split samples, each with pass thresholds, an on-fail action and
  what it unlocks. `scripts/run.py` enforces them through `experiments/gates.yaml`.
- New experiments: E003 (attention shift, the test of H2 that the old plan lacked), E004 (paging
  fidelity under teacher forcing, masked simulation), E005 (overhead microbenchmark), E006 (accuracy
  vs memory, pilot then main). E000–E002 were re-tiered.
- The dump now stores a two-tensor summary of the text keys per step instead of the text KV: gate
  dump at most about 3.5 GB, main dump at most about 27 GB (was about 100 GB). One capture serves
  both G2 and G3.
- Gates and tuning use a fixed dev split (150 per dataset, nested subsets); main tables report the
  full benchmark and the test split alone.
- Tests: 45 pass on CPU, including both dump-based runners end to end on a small fake dump, and the
  runner refusing a held experiment.
- Synthetic code check of the new budget metric (`runs/E001-pooled-attention-fidelity/*-synthetic`,
  not a result): with the oracle top 25% of regions exact at g=2, median error is 0.029 with
  stand-ins vs 0.080 with the rest dropped.
- The thresholds were chosen without data (Q13). Review them after G1–G3.
